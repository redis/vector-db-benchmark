# vector-db-benchmark 0.2.0

0.2.0 is the first release of the Rust implementation. 0.1.0 (2026-02-12) was
the Python tool, which is now frozen in `v0/`. This release covers everything
merged to `master` since then. Each item below cites the pull request it comes
from. The rewrite itself was promoted to `master` as direct commits, without a
PR, so those items cite commit SHAs instead.

## Highlights

- **Rewritten in Rust.** One `vector-db-benchmark` binary replaces `run.py`,
  plus `prepare-msmarco`, `generate-dataset` and the reader micro-benchmarks.
  The Python tool is kept, unchanged, in `v0/` (promotion commit `646b718`).
- **15 engines, up from 8.** New since 0.1.0: Valkey (`ac15563`, ElastiCache
  Valkey 9.1 grid in #89), MongoDB (`b34e0f9`), Turbopuffer (`99dae96`),
  Dragonfly (#132, filtering in #192), Google Cloud Vertex AI Vector Search
  (#144, #149, #150, #195), Chroma (#185) and KiviDB (#203). They join Redis,
  VectorSets, Elasticsearch, OpenSearch, Qdrant, pgvector, Weaviate and Milvus.
- **Filtered search on every engine that can express it.** `match_any` IN-lists
  (#78, #80, #81, #83, #84, #85, #86, #106), bool, uuid, full-text and datetime
  fields (#102, #164–#170, #180, #181), geo radius (#171, #172, #286),
  multi-valued keywords (#142) and nested AND/OR groups (#183). A filter that an
  engine cannot express is now a hard error, not a silently unfiltered run
  (#107, #233, #251).
- **Hybrid, full-text and filter-only workloads.** Qdrant sparse vectors and
  dense+sparse RRF fusion (#69, #104), ColBERT-style multi-vector on Qdrant
  (#316), ranked BM25 full-text on Redis and OpenSearch (#353, #358),
  filter-only benchmarks (#328, #354), hybrid prefilter + KNN with filtered
  ground truth (#357), and one ingest serving many workloads (#351, #360).
- **MS MARCO v2.1 + Cohere embed-v3 datasets** with real document metadata, from
  100K up to a 100M variant larger than RAM, with streamed preparation and
  upload (#319, #322, #350, #361).
- **Redis HNSW SQ8 and SVS-VAMANA.** HNSW SQ8 compression, with an SQ8
  counterpart for every SVS calibration benchmark (#325, by @dor-forer).
  SVS-VAMANA with LVQ/LeanVec compression (#157, #159), and SVS calibration
  that takes effect (#206, by @mihaic).
- **KiviDB 1.1.2.** Multi-valued TAG labels and CI on the latest stable KiviDB
  (#381, by @murtazayusuf). Every TAG filter value is now sent escaped and
  matched exactly, or refused (#375).
- **Measurement you can trust.** All workers start together after a per-worker
  warm-up (#193). Only the RPC is timed (#74, #111, #113, #114). Recall@k is
  corrected and failed queries are excluded from the scores (#71). Percentiles
  match numpy (#94), each config is repeated and the best run kept (#95), and
  results add p90 (#349), worst-decile recall (#174) and saturation detection
  (#92, #179).
- **Results that say how they were produced.** `--version` and `params.build`
  name the commit and build (#369). Each result records the environment knobs
  and the declared config the run used (#264). `--dump-results` writes per-query
  records, and `compare-results` diffs two runs (#351). Latencies are stored as
  compact HDR digests instead of raw arrays (#156).
- **Prebuilt binaries.** Linux x86_64/aarch64 and macOS arm64 archives with
  `SHA256SUMS` and a checksum-verifying install one-liner (#369). Native
  .deb/.rpm packages are built and install-tested for every release (#370), but
  not yet published (see below).
- **Fuzzed dataset readers.** A nightly cargo-fuzz harness covers the dataset,
  RESP and datetime parsers (#135, #138, #139).

## Breaking changes

### Since 0.1.0 (the Python release)

1. **The Python CLI and package are gone.** `python run.py …` and the Poetry
   package `vector-benchmark` are replaced by the `vector-db-benchmark` binary
   (`646b718`). The Python CI and PyPI publish workflows were removed in
   `6fa1d77`. Most flag names carry over (`--engines`, `--engines-file`,
   `--datasets`, `--parallels`, `--host`, `--skip-upload`, `--skip-search`,
   `--skip-if-exists`, `--exit-on-error`, `--timeout`, `--upload-start-idx`,
   `--upload-end-idx`, `--queries`, `--ef-runtime`, `--describe`,
   `--verbose`). See items 3 and 4 for the ones whose meaning changed.
2. **Docker invocation.** The image's entrypoint is now the binary itself
   (`3036fac`). Use `docker run redis/vector-db-benchmark --host … --engines …`.
   The 0.1.0 form, `docker run redis/vector-db-benchmark run.py --host …`, no
   longer works.
3. **Boolean flags take a value, not a `--no-` prefix.** Typer's
   `--no-skip-if-exists` / `--no-exit-on-error` forms do not exist. Use
   `--skip-if-exists false` / `--exit-on-error false`. A bare flag still means
   `true` (#60).
4. **`--timeout` is an overall wall-clock budget.** In 0.1.0 it was a
   per-experiment hard abort. Now no new experiment starts once the budget is
   spent, and the experiment in flight finishes. `0` disables it (#64).
5. **174 of 0.1.0's 310 engine config names were removed.** These are all of
   `redis-vector-types.json`, `redis-raft_ivf_flat-single-node.json`,
   `redis-raft_ivf_pq-single-node.json`, `redis-intel-hnsw-single-node.json`,
   `redis-hnsw-single-node.json` and `redis-vs-azure-ai-search.json`
   (`b76d5b9`), plus `redis-default-simple` (`4f82f1d`). The standard Redis
   grid is the `redis-m-*` configs. Run `vector-db-benchmark --describe engines`
   for the current list.
6. **Dataset renamed:** `dbpedia-openai-1M-1536-angular-100neighbors` is now
   `dbpedia-openai-975K-1536-angular-100neighbors`, because the archive holds
   975,000 vectors, not 1,000,000. There is no alias. Update saved `--datasets`
   arguments and any comparison keyed on the old name (#325).
7. **Result JSON keys.**
   - `mean_precisions` is renamed `mean_precision_at_returned` (same value).
     Upstream qdrant/vector-db-benchmark uses `mean_precisions` for what this
     tool calls `mean_recall`, so the old name was misleading. Result files carry
     a `metrics_schema` block, and summaries carry `metrics_schema_version: 2`
     (#249).
   - The per-query `latencies` and `precisions` arrays are no longer written by
     default. They are replaced by a `latency_hdr` digest and `*_dist`
     histograms. `--dump-raw-latencies` writes the raw arrays as well, with the
     precision array named `precisions_at_returned` (#156, #249). Top-level
     `mean_*`, `p50_time`, `p95_time`, `p99_time` and `rps` are kept.
8. **Indexes uploaded by an older build cannot be reused.** Each config now gets
   its own index and key prefix on Redis, Valkey and Dragonfly (#153), its own
   vector-set key on VectorSets (#278), and its own collection on MongoDB (#308).
   `--skip-upload` against data written by 0.1.0 is refused: upload again.
9. **Strict `FT.INFO` read-back on every Redis vector config.** After
   `FT.CREATE`, and again before every search, the vector field's algorithm,
   compression and training threshold are checked against the config. This
   covers plain HNSW and FLAT too. A server whose `FT.INFO` has no `attributes`,
   or reports no per-field `algorithm` (RediSearch older than 2.8), now fails
   the run. So does reusing an index of another algorithm or compression under
   the config's name (#325).
10. **SVS LVQ/LeanVec configs need a server with Intel's SVS optimisations.** On
    any other server, RediSearch silently builds `GlobalSQ8` instead. Such
    servers include stock Redis Open Source, the official `redis` Docker images
    (even on Intel x86) and every non-Intel CPU. The `*-cal-svs-LVQ*`,
    `*-cal-svs-LeanVec*` and `redis-compare-*-svs-lvq8` configs used to publish
    results under the wrong compression name on those servers. They now fail.
    Uncompressed SVS is unaffected (#325).
11. **Runs that used to finish with a wrong number now fail.**
    - A filter that parses to nothing (#251), or that the engine cannot express
      (Qdrant #233, KiviDB #237, hybrid #357).
    - Duplicate engine or dataset names, or a config file that fails to parse
      under a glob (#250).
    - `--engines-file` now reads only that file, and a missing or malformed file
      is an error (#152).
    - A filter-only glob that matches several configs of one engine (#328).
    - A corpus that holds more vectors than `datasets.json` declares (#244).
    - `--skip-upload` when the server holds fewer rows than the corpus, when the
      probe fails (#271), or when the corpus size cannot be determined (#295).
    - An expired post-upload indexing wait on Redis, Valkey, Dragonfly and KiviDB
      (#361).
    - A worker thread that fails to start or panics (#263).
12. **OpenSearch configs pin `number_of_shards`, and `--engines 'opensearch-*'`
    now matches two shard counts.** Every shipped config pins its shard count.
    `opensearch-single-node.json` pins 1, and the new `opensearch-5-shard.json`
    (configs `opensearch-5-shard-*`) pins 5. A bare `opensearch-*` glob selects
    both and sweeps two shard counts into one report. Select one file with
    `--engines-file` (#235).

### Changed on `master` since 0.1.0 (affects master builds only)

These features did not exist in 0.1.0. They changed in incompatible ways before
this release.

13. **KiviDB TAG fields require KiviDB ≥ 1.1.2.** On an older server, or one
    whose version cannot be read, a dataset with TAG fields is refused. Vector-only
    and numeric/text-only datasets still run. CI moved from 1.0.2 to
    `kividb/kividb:v1.1.2-full` (#381). TAG values are now escaped. A value
    with no exact encoding is a hard error: one containing `;`, ending in `*`,
    starting with `$`, with leading or trailing whitespace, empty, or with
    whitespace other than a space inside it (#375). Geo filters are refused on
    KiviDB, which has no geo field type (#237).
14. **MongoDB configs renamed** to `mongodb-m-{M}-efc-{EFC}`. They now pass
    `M` / `EF_CONSTRUCTION` to Atlas as `maxEdges` / `numEdgeCandidates`. The
    query-time `ef` sweep, which MongoDB ignored, is removed, and the sweep
    varies `num_candidates` instead (#241).
15. **MS MARCO datasets renamed.** The position-sampled ("prefix") variants were
    dropped. The hash-sampled ones are now
    `msmarco-cohere-1024-{100K,1M,10M}-cosine`, with new row counts and paths
    (#322). `prepare-msmarco` refuses to rebuild over an old corpus without
    `--add-derived-fields` (#350).
16. **Mixed-workload `update_count`** counts updates the server accepted into the
    searched corpus, not client-side attempts. New fields:
    `update_failures`, `update_unattributed`, `update_attribution` and
    `update_attribution_detail` (#298).
17. **Summary shape.** A config that mixes vector and full-text workloads gets a
    `workloads` list and a per-row `workload`. Its full-text rows are left out of
    the precision buckets and concurrency curves (#360). Filter-only results
    have no vector-quality fields. Check `workload` before reading them (#328).

## Upgrade notes

- **Install.** Pick one of these:
  - The install one-liner:
    `curl -fsSL https://raw.githubusercontent.com/redis/vector-db-benchmark/master/scripts/install-release.sh | bash`.
  - A release archive, checked against `SHA256SUMS`. The Linux archives need
    glibc 2.34 or newer (#369).
  - The Docker image.
  - A source build with `make vector-db-benchmark`.
- **Linux packages are not published yet.** The .deb/.rpm packages are built and
  install-tested on every release, but publishing to packages.redis.io is
  switched off for now (#370). Use the archives.
- **Datasets.** To avoid re-downloading DBpedia 1536, move
  `datasets/dbpedia-openai-1M-1536-angular-100neighbors/dbpedia_openai_1M/` to
  `datasets/dbpedia-openai-975K-1536-angular-100neighbors/dbpedia_openai_975K/`
  (#325).
- **Re-upload data from older builds.** Do not point `--skip-upload` at data
  written by 0.1.0 or by early master builds (#153, #278, #308).
- **Scripts.** Drop `run.py` from Docker commands. Replace `--no-<flag>` with
  `--<flag> false`. Re-select engine configs by their current names
  (`--describe engines`).
- **Result consumers.** Read `mean_precision_at_returned` instead of
  `mean_precisions`. Read latency percentiles from the top-level fields or
  `latency_hdr`, and dispatch on `workload` (#156, #249, #328).
- **Comparing against 0.1.0 numbers.** Don't compare them directly. The client
  is new, and the timed window, recall and failure accounting and several engine
  setups changed. Examples: RPC-only timing (#74, #111, #113, #114), failed
  queries excluded (#71), previously dropped filters now applied (#107), Milvus
  scalar indexes (#242), and OpenSearch/Elasticsearch segment and refresh
  settings (#246, #248). Re-run both sides with 0.2.0.
- **Redis SVS LVQ/LeanVec** benchmarks need an Intel SVS build of Redis (#325).
  **KiviDB** TAG datasets need 1.1.2 (#381).
